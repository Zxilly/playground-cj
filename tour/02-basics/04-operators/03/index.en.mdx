# Assignment Operators

The assignment operator `=` is used to assign a new value to a variable declared with `var`. Unlike many languages, the type of an assignment expression in Cangjie is `Unit`, and its value is `()`. This means assignment expressions cannot be used as conditions or chained (such as `a = b = 0`), helping you avoid the common mistake of writing `=` instead of `==`. During assignment, the right-hand side is always evaluated before the left-hand side.

Cangjie supports compound assignment operators that combine an operation with assignment: `+=`, `-=`, `*=`, `/=`, `%=`, `**=`, `&&=`, `||=`, etc. For example, `score += 5` is equivalent to `score = score + 5`, but more concise. Compound assignment operators require both operands to be of the same type.

Cangjie also supports multi-assignment expressions, allowing you to assign tuple values to multiple variables at once. For example, `(a, b) = (b, a)` can conveniently swap the values of two variables.

C's assignment expressions have a return value (the value after assignment), which can be used in conditional statements. This can easily lead to the common mistake of writing `=` instead of `==`. Cangjie's design is safer.

<CompareWith lang="java">
Java's assignment also has a return value and can be used in conditions, similarly prone to confusing `=` with `==`. Java supports compound assignment operators like `+=`.
</CompareWith>

<CompareWith lang="go">
Go's assignment statement does not return a value, so using assignment in a condition is a compilation error, similar to Cangjie. Go also supports compound assignment operators like `+=` (though not `**=`) and multi-variable assignment `a, b = b, a`.
</CompareWith>

<CompareWith lang="rust">
Rust's assignment expressions return `()`, just like Cangjie, likewise disallowing chained assignment and assignment in conditions, while supporting compound assignment operators and tuple destructuring assignment `(a, b) = (b, a)`.
</CompareWith>
