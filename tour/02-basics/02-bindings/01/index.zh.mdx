# let（不可变绑定）

`let` 关键字用于创建不可变绑定，将一个名字与值关联起来。一旦绑定完成，该名字就不能再指向新的值。这种不可变性是仓颉的默认选择，有助于编写更安全、更易推理的代码。

在仓颉中，变量定义的基本形式是：`修饰符 变量名: 变量类型 = 初始值`。其中 `let` 修饰符表示该变量不可变，且声明变量时修饰符不可省略。`let` 修饰的变量只能被赋值一次，即在初始化时赋值。需要注意，不可变绑定仅表示该绑定本身不能重新指向另一个值；如果它持有的是可变对象的引用，对象内部的内容仍然可以被修改。

右侧代码定义了三个不可变绑定：`name` 绑定到字符串，`year` 绑定到整数，`pi` 绑定到浮点数。每个变量的类型都由初始值自动推断。如果尝试取消注释 `// name = "其他"` 这一行，编译器会报错——`let` 绑定的值不能被重新赋值。

<Note>局部变量支持延迟初始化（先声明类型、稍后再赋值），但必须在被引用前完成初始化；全局变量和静态成员变量必须在声明时初始化。</Note>

<CompareGroup>

<CompareWith lang="c">
C 可以用 `const` 为对象或指针表达不可修改约束，但 `const` 不等同于编译时常量。仓颉则用 `let` 声明不可重新赋值的绑定。
</CompareWith>

<CompareWith lang="java">
Java 用 `final` 修饰符声明不可变变量，语义接近仓颉的 `let`。
</CompareWith>

<CompareWith lang="go">
Go 使用 `:=` 声明变量，声明的变量始终可变，没有不可变变量的概念。仓颉的 `let` 提供了不可变性保证。
</CompareWith>

<CompareWith lang="rust">
Rust 的 `let` 也默认不可变，语义与仓颉相同，但 Rust 允许同作用域内变量遮蔽（shadowing），仓颉不允许。
</CompareWith>

</CompareGroup>
